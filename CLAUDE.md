# Starbase: notes for Claude

Community gallery for Datastar Rocket web components. Go 1.27, templ, SQLite (modernc, pure Go), Datastar v1.0.4 + Rocket (vendored in `static/vendor/datastar-rocket.js`).

## Commands
- `go tool task live`: dev server (air, `-tags dev`, live reload via `/dev/reload`)
- `go tool task test`: `go vet` + `go test ./...`. `TestCodeEditorLinesAlign` (`internal/app`) drives headless Chrome like `cmd/manifests`: it skips without Chrome, and without a sandbox unless `STARBASE_CHROME_NO_SANDBOX=1`. Run `go tool templ generate` after editing `.templ` (the `_templ.go` files are committed).
- `go tool task new -- <slug> --category <cat>`: scaffold a component
- `go tool task manifests`: regenerate all `manifest.json` in headless Chrome (`cmd/manifests`, runs the app in-process); `--check` in CI. Dev pages publish them from the readable modules (`/c/index.js`, and only those: the bundle and `.min` files are shrunk, see Versioned URLs). Chrome keeps its sandbox (submitted code runs there); on machines without one, set `STARBASE_CHROME_NO_SANDBOX=1` (never in CI).

## Performance and SEO
- Responses to GET/HEAD are compressed (brotli/zstd/gzip, `web/compress.go`); render streams (POST) compress themselves and bypass it. Set `Vary` with `Add`, never `Set`.
- Pages load every component as **one bundle** (`/c/bundle.js`, esbuild, `catalog.Bundle`; lazy `import()`s stay lazy) while its brotli size fits `web.bundleBudget` (100 kB); over budget they fall back to the autoloader, with a warning at startup. `?load=auto` / `?load=bundle` override it for measuring. Measured on production: the bundle wins any visit that includes the homepage and costs a single-page lander ~265 ms on slow 4G at 66 kB. The bundle also removes `sb-cloak`, like the autoloader.
- Static and generated assets (component modules and `.min` files, the autoloader, `/c/bundle.js`, CSS bundles, art, text files under `/static/`) go out **precompressed** (`internal/precompress`: brotli -11 and gzip -9, memoized by content, warmed in the background at startup); the middleware skips anything with `Content-Encoding` set. Only HTML documents are compressed per request. The catalog's size tables measure through the same cache, so a size shown is the bytes sent.
- Hashed static files are `immutable`. `robots.txt`, `sitemap.xml` (pages + active components), `/og.png`, `/apple-touch-icon.png` and `/favicon.ico` (PNG, rendered from the pixel art: `pixelart/png.go`) are in `web/seo.go`. Every page has a canonical URL, Open Graph/Twitter tags and JSON-LD (`WebSite` with a search action; component pages add `SoftwareSourceCode` via `view.Schema`).

## Deploy
- `deploy/`: host files (systemd unit, env, Caddy snippet), `starbase-deploy` (root; verifies, restarts, checks `/healthz`, rolls back) and `setup-host.sh` (the restricted `starbase-deploy` user with a forced-command key). `.github/workflows/deploy.yml` runs after CI on `main`, gated by the repository variable `DEPLOY_HOST`.

## Architecture rules (CQRS)
- State changes are **commands** (`internal/commands`): structs with `Apply(ctx, *sql.Tx)`, optional `Validate()`, and `Scope()` (session id) when only that session's views change. Handlers call `bus.Send` and return 204. Commands never render HTML.
- Only the `cqrs.Bus` writes to the database (single writer, `db.W`). Queries use `db.R` through `queries.Queries.View` (one read tx per render).
- Pages are `pageFunc`s in `internal/web` registered with `s.page(mux, pattern, fn)`, which gives the GET document and the POST render stream. A page must be a pure function of `renderCtx`.
- Per-tab UI state goes in `tab_state` via commands, never in handler memory or client-only signals.
- Preferences that should outlive a page (they carry across navigations and browser tabs) are session preferences (`session_prefs`, keyed by sid, set by commands, read into `renderCtx.prefs`, so the first GET renders them); `tab_state` lives for one loaded page (`tabid` is new on every document). A new preference is one field in `model.SessionPrefs` plus its command (`commands/prefs.go`), like `SetInstallTab`. Today: the install tab, the Themes preview (`SetPreviewTheme`, `SetPreviewStyle`) and the gallery's default sort (`SetGallerySort`, `POST /cmd/sort`): a page without stored state takes the sort from its URL when it names one, else the session's (`BrowseFromQuery(q, prefs.DefaultSort())`), and `Browse.QueryFor` drops the sort from URLs only when it and the default are both "popular". Search and category (`/cmd/browse`) never change the default.
- Exception: the site theme is a browser preference, kept by `sb-theme-switch` in the `sb-theme` cookie. The layout renders it (`Shell.Theme`, `siteTheme`) on `<html data-sb-theme>`, so there is no flash. "auto" means no attribute: `:root` is deep-space, and `/theme/auto.css` (generated from the daylight block in `css/themes/showcase.css`) applies daylight on light systems.

## Frontend rules
- 8-bit details are opt-out: pixel-corner clip-paths scale with `--sb-notch` (1 or 0; at 0 use a border radius), frames with `--sb-frame-step`, display text uses `--sb-font-display`. `[data-sb-style="smooth"]` (theme.css) sets all three; the Themes page switch is the session preference `SessionPrefs.PreviewSmooth`.
- CSS: `@layer reset, tokens, theme, base, layout, components, utilities`. Pages load one minified bundle (`/bundle/site.css`, built at startup from `siteStylesheets` in `web/assets.go`, font URLs rewritten to hashed names); a new stylesheet must be added there. The playground runner gets `/bundle/runner.css`.
- Fonts: component text sets no `font-family` of its own, so it inherits the page's. Where a component uses a font token, text falls back to the page's font, not to a named font: `font-family: var(--sb-font-display, inherit)`, or, for a canvas that needs a font name, the element's computed `font-family` when the token is unset (`sb-echarts` `font()`). Only code (editor, console) falls back to monospace. On Starbase the tokens are set, so nothing changes there.
- Syntax colours are semantic tokens (`--sb-code-keyword|function|tag|string|number`), with light values in the daylight block; don't use palette primitives (`--sb-violet-3`…) for anything that must work on light themes. Use semantic `--sb-*` tokens (theme.css) in components, not primitives. Prefer container queries over media queries.
- **Wire components declaratively:** events use `data-on:*` with local `action()`s (`@name()`), state is `$$` signals with `data-bind`/`data-show`/`data-class`/`data-attr`/`data-text`/`data-effect`, lists use `<template data-for>`, and elements come from `data-ref:x` → `onFirstRender({ refs })` (refs are not `$$` signals). `data-bind:x` in rendered markup binds the local `$$x`. Plain `addEventListener` is only for things without an attribute form (`matchMedia`, Intersection/ResizeObserver), and for window/document listeners: `data-on:*__window` inside a shadow template outlives the element and throws `UndefinedAction` after removal, so add those in `setup` and remove them in `cleanup`.
- Rocket components (`components/<slug>/`): shadow DOM (default mode), `adoptStyles(host, css)`, `--_x: var(--sb-x, fallback)` locals, interaction state in `$$` signals (never reflected to attributes, because server morphs reset attributes), `emit()` for events, `.docs()` on every prop.
- **Known upstream issue:** Datastar's morph is not re-entrant, and Rocket renders synchronously in `connectedCallback`. Never put `id`s on repeated or reordered elements that contain Rocket components (e.g. gallery cards). The morph would park and move them and crash (`Maximum call stack` / `moveBefore` HierarchyRequestError). Minimal repro and a proven fix are in `docs/repro/rocket-morph-reentrancy/` (upstream: starfederation/datastar#1209).
- `data-bind` on a custom element only writes to an existing signal. Declare it with `data-signals` first, and use `__prop.value` / `__prop.checked`: Datastar binds before Rocket upgrades the element, and otherwise falls back to the attribute, which morphs strip.
- Component host getters and setters over `$$` (`overrideProp`) must use `startPeeking()`/`stopPeeking()`, or `data-bind`'s effect subscribes to the internal signal and writes stale values back.
- The server can set every value: a form component's `value`/`checked` attribute **wins when the server sends a new one** (`observeProps` on that prop). Re-sent identical markup changes nothing, so user edits survive morphs. A *removed* attribute is ignored (`host.hasAttribute` check): morphs also strip attributes that were only reflected, e.g. by Rocket's upgrade replay of a `data-bind` write made before the element was defined. To clear, the server sends `value=""` / `checked="false"`. Property writes go through `overrideProp` into `$$` and never reflect. Rocket replays pre-upgrade property writes into `props` itself: no manual adoption needed.
- Command contract for value components (input, slider, toggle, code-editor, tabs; rating, select, tree): a `name` prop; `sb-change {name, value}` on commit; `confirm` sets `:state(pending)` (ElementInternals custom state, `internalsOf(host)` caches the internals since `setup` reruns on re-attach) while `$$` differs from the server's attribute; `host.revert()` restores the server's value. Pages: `data-on:datastar-fetch="evt.detail.el === el && evt.detail.type === 'error' && el.revert()"` (fetch events reach every listener). Demo: `SetFlight` / `POST /cmd/flight` / `ui.FlightDemo` on the Showcase.
- A server that normalises a value back to what it already held sends identical markup, so the component can't tell "answered" from "not yet": `sb-input` takes an optional `rev` (a revision the server bumps with every applied command, e.g. `CallsignRev` on the Showcase) and treats a new `rev` as the server's word. Other value components don't have it yet.
- Every component: `:host([hidden]) { display: none }` wherever `:host` sets `display`; styles for `disabled` (and other booleans) come from the decoded prop (`:state(disabled)` or the inner control's `:disabled`), never `:host([disabled])`, which also matches `disabled="false"`; a `@media (forced-colors: active)` block keeps focus rings (a transparent outline) and glyphs (`CanvasText`) visible; a token's hex fallback is the same in every component (`TestTokenFallbacksAgree`).
- No optimistic updates: never show a server result (counts, lists, derived values, success messages) before the server renders it; the user's own input stays, marked `:state(pending)` (or faded items for operations), and `revert()` on rejection.
- Several values: parts of one decision are one structured `value` (JSON attribute, one `sb-change`, one command; e.g. `sb-range` `{start, end}`); view state (`expanded`) is a separate prop and event, never pending; server data (`results`, `options`) only flows in; operations (paint, move) emit `sb-<verb>` with per-item pending until the echo.
- Server data for components are props the server can morph (e.g. `sb-select` `results`, `sb-tree` `loaded`/`expanded`), not only signals.
- Rocket/Datastar gotchas (learned the hard way):
  - `observeProps` only fires when the *decoded* value changes (`#setProp` returns early on `Object.is`). So `checked="false"` written onto an element that never had the attribute is silent, and a local edit would survive a server clear. Every value component therefore watches its value attribute itself (`new MutationObserver(…).observe(host, { attributeFilter: ['value'] })`, the pattern in `sb-details`) and applies server-wins there; `TestServerWinsContract` (`internal/app`, Chrome) checks all of them (a JSON value like `sb-range`'s may use observeProps, since its codec never decodes to the default).
  - Never call a component `action()` from `data-effect`: Datastar's effect flush can run it after the element was cleaned up (`UndefinedAction`, and the replacement element renders empty). Use `effect()` in `setup` instead.
  - Host ARIA that must survive a morph goes through `ElementInternals` properties (`internals.ariaBusy`, `internals.role`), like `:state()`; an attribute set from an effect is stripped by the next morph and the effect never re-runs.
  - Assigning an object to a signal *merges* into it (keys are never removed), and reading a missing key creates it. Keep maps and sets that change in plain closure variables, and expose only what the template renders (e.g. `$$.rows`).
  - `observeProps` callbacks run inside the effect of whoever set the attribute (e.g. `data-attr:x`): wrap them in `peek()`, or their signal reads subscribe that effect (infinite loops).
  - With `renderOnPropChange` (the default) every prop change re-renders the whole template, dropping keyboard focus. Components with focus or live state: `renderOnPropChange: false`, and drive the markup through signals.
  - Style rows by a prefix or class (`[role^="menuitem"]`), never an exact `[role="menuitem"]`, in a component that can change a row's role: the value-bearing variant (`menuitemradio`) silently loses every rule, and a presence-only test won't see it.
  - Lists that hold focus (tree, menu, radio group): a morph parks a row before removing it, so `focusout` arrives with the row still connected and `relatedTarget === null`, exactly like a click on the page. Decide it a microtask (or a frame) later: row gone → the server dropped it, keep the flag; row still there → the user left, clear it (treating every null as "not leaving" made the group steal the focus back on the next server update). Restore focus only when `document.activeElement` is the body or the host, and move to the *neighbour* of a dropped row (old index clamped), not the first. Documented for contributors in contribute.md.
  - `<template data-for>` can re-evaluate a removed row once with the loop variable undefined when the list shrinks: use `r?.x` in row expressions.
  - Server data for a component: it emits an event (`sb-load`, `sb-search`), the page answers with `@get`, the server patches a signal (or morphs the prop), `data-attr` hands it back (see `sb-tree`, and the generic `/demo/data/…` endpoints for demos).
- Hosts whose attributes are driven by signals (`data-attr:x=...`) need `data-preserve-attr="x ..."`: the morph resets every attribute to the server markup.
- Pixel art (`internal/pixelart`) is generated SVG. Theme-aware colours are `var(--sb-art-*, #fallback)` (set per theme in `css/themes/showcase.css`; Deep Space uses the fallbacks), which only apply where the SVG is inlined with `ui.Art` (logo, hero). As `<img>`/favicon the fallbacks show. Its CSS is scoped under `.px-art`.
- `tab_state` is for server-owned UI state of one page (the gallery's search and category, the playground share); choices that should last (install tab, Themes preview theme and style, the gallery's default sort) are session preferences. High-frequency, ephemeral demo state (sliders, playgrounds) stays in local `_`-prefixed signals.
- `unlisted: true` in a component's front matter keeps it out of the gallery, the search index, the sitemap and the site stats, while it stays served, versioned and documented at `/components/<slug>` (migration 007 adds `components.listed`). It is for components the site itself runs on: `sb-code-playground` powers `/playground`.
- Component pages render an auto Playground from the manifest (`internal/catalog/playground.go`, `ui.Playground`). It is a `data-ignore-morph` island driven by local `$_pg` signals, tuned by `playground:` front matter.
- `GET /demo/telemetry` (`internal/web/demo.go`) is a stateless query stream of `$_tm` signal patches for live demos.
- Demo data for components' docs comes from the example dataset (`internal/demo`, seeded by `SeedDemo`): use the generic `GET /demo/data/children` and `/demo/data/search` (`internal/web/demo_data.go`, `&into=` names the signal, `&delay=` for loading states) instead of adding component-specific endpoints.
- Canvas components: `renderOnPropChange: false`, repaint on `observeProps`, read theme tokens at paint time (via a 1×1 canvas probe), pause offscreen (IntersectionObserver) and honour `prefers-reduced-motion`.
- The CSP uses a nonce (import map) plus `'unsafe-eval'` (Datastar). No inline `<script>` without `s.Nonce`. `script-src` allows only `<origin>/static/` and `<origin>/c/`, not `'self'`: new script locations must be added there.
- Rate limits (`limiter`, per session and per `clientIP`, which trusts `X-Real-IP` only from loopback/Unix-socket peers): painting, snippet saves. Snippet storage is capped (`MaxSnippetStore`, tracked in `snippet_stats`).

## Submissions
- `.github/ISSUE_TEMPLATE/new-component.yml` is the "Submit a component" form (`/submit` redirects to it). Its labels must match `internal/submission` (a test enforces it).
- `.github/workflows/component-from-issue.yml`: `build` (read-only, runs untrusted code only there: `cmd/fromissue` then `cmd/manifests`) → `pull-request` (write, never executes submitted code) / `report-failure` (comments on the issue).
- Submissions may link a public GitHub repo; `submission.Fetch` pins the commit, recorded as `source:` front matter (shown as a Source link). Playground links set no `source:`. Imports are checked for every submission (`submission.Imports`): only `'datastar'` and relative files inside the component folder; with a repo link the bot vendors every file the component reaches (≤ 2 MB each, 4 MB total). Vendored files are proven via `vendor.json` (`submission.VerifyVendor`: byte-for-byte against the npm tarball, which must match the registry's integrity hash); unverified minified code is refused, unverified readable code is flagged in the PR notes. CODEOWNERS covers `components/**/vendor/`.
- The playground resolves relative imports in `component.js` against `base` (`/c/<slug>/`, or `/playground/preview/<commit>/<slug>/` which proxies the pinned commit's `.js` files).
- Every submission PR lists similar catalog components (`submission.Similar`, in the PR body) and gets a preview comment per revision: `/playground?preview=<commit>/<slug>` (`internal/web/preview.go`) fetches that commit's files from the repo on raw.githubusercontent.com, memoized per commit (immutable).

## Versioned URLs
- Minified modules (`catalog/min.go`, esbuild): every module file `x.js` has a `x.min.js` sibling whose relative imports point at the `.min` files. The autoloader, the site (`assets.ComponentScript`) and the playground's deps load `.min`; the readable file stays the default URL for docs, the playground editor and "view source". Before minifying, `catalog/shrink.go` takes out what esbuild can't (non-vendored files only): `.docs({…})` calls and the rocket() `manifest: {…}` property (manifest.json is published from the readable modules), and comments and needless whitespace in `/* css */` and `html`/`svg` templates (–18% on modules, –16% on the bundle). A module may use the `manifest:` key only for rocket()'s (a test enforces it); `TestShrunkModulesKeepProps` (`internal/app`, Chrome) checks the bundle still defines every prop of every manifest. `.min` bytes depend on the esbuild version and on shrinking, so they are frozen per version, and a change to either must bump `minFormat` (`catalog.go`, part of every component's hash): `SyncCatalog` stores them in `component_files` (INSERT OR IGNORE) and `serveVersioned` always serves `.min` from there (in memory only before the first sync). Install snippets are built in `Server.install` (`web/views.go`, rendered by `ui.Installation` as `sb-tabs`: Autoloader, This component + its `Catalog.Deps`, Pinned snapshot, Self-host); they pin `.min` with that frozen integrity (`Reader.FileIntegrity`). The chosen tab is the session preference `SessionPrefs.InstallTab` (`POST /cmd/install-tab`, stored by key, not index).
- Download sizes: `catalog.Load` computes `Component.Sizes` over the files a page loads (`Catalog.Loaded`: the main module and what it imports; a module only the examples use, like autoloader's `demo-badge.js`, is served but not counted), each compressed on its own at gzip -9 / brotli -11; `Uses` = components it renders, transitively (`Catalog.Deps` over `Catalog.Uses`), which the autoloader's `requires` also uses). `Size.Min` is the minified file under brotli (what a page downloads): gallery cards show `Sizes.Total.Min`; `ui.SizeTable` on component pages has both.
- `internal/web/versions.go`: `/c/<slug>@<hash>/<file>` (a component version: current from the binary, older from `component_files`), `/c/@<catalog hash>/autoloader.js` and `/importmap.json` (SRI map). All immutable, `ACAO *`. `SyncCatalog` stores every version and catalog snapshot it sees (migration 005), so pinned URLs outlive deploys.
- The site uses versioned module URLs too (`assets.ComponentScript`, `catalog.AutoloaderJS`); the old `/c/<slug>/<file>` route stays for compatibility.

## Code playground
- `/playground` page (`internal/web/playground.go`, `ui.CodePlaygroundPage`): sources `?s=<snippet>`, `?component=<slug>` (JS + `Component.Examples`), or a starter. The editor area is a `data-ignore-morph` island; the share strip around it is stream-rendered from `tab_state.PlaygroundShare`.
- `sb-code-editor` highlights with Prism, vendored as an ES module in `components/code-editor/vendor/prism.js` (js-templates plugin, plus `/* css */` templates and `data-*` values as JS). Rebuild it with `go tool task vendor-prism`. Components may import `'datastar'` or files in their own folder; `/c/<slug>/**.js` is served.
- `/playground/run` is the sandbox runner (own CSP, opaque origin via `sandbox="allow-scripts allow-modals"`, a fresh iframe per run). It adds a loop guard to the user's code (a `while`/`for(;;)` condition that runs a single task for over a second throws), since Chrome runs every sandboxed frame of a site in one process and an endless loop would freeze every playground on the page; the component also has a watchdog for runs that never answer. The protocol is documented in `components/code-playground/README.md`. Public assets send `Access-Control-Allow-Origin: *` for it.
- Rocket gotcha: before Datastar is ready, a later `rocket()` call for the same tag replaces the queued one, so the runner imports the edited code first and the parent drops deps whose tags the code defines.
- The size line in the playground's top bar (`ui.PlaygroundSize`, in `sb-code-playground`'s `bar` slot) is a query, not a command: `POST /playground/size` (`web/playground_size.go`, rate-limited, memoized by content) measures `component.js` with `Catalog.Measure` (the catalog's esbuild settings, uncached `precompress.BrotliLen`) and patches `$_size` with preformatted texts; a parse error patches only `stale`, so the last numbers stay. The first numbers are rendered with the page. It hides detail with container queries on `.code-page__island` (`container: playground`).
- Snippets: `SaveSnippet` (≤ 64 KB, immutable, `snippets` table). `GET /playground/snippet/{id}` is public JSON. The submission bot imports playground links only from `STARBASE_URL`.

## Pixel board
- `sb-pixel-board` takes `cells` from the server (not preserved: every morph brings the latest). The board section on `/showcase` is **not** an ignore-morph island; Mission Control is.
- `PaintPixels` / `SeedBoard` in `internal/commands/board.go`; the encoded board is cached per version in `web.boardState`; `/cmd/paint` has an in-memory token bucket (20 px/s, burst 60).
- Paint posts use `requestCancellation: 'disabled'`: Datastar cancels in-flight requests to the same URL by default, which would drop pixels mid-stroke.
- `cqrs.Hub` knows each stream's path: `Count(path)` for presence; joins and leaves wake that path's streams.
- `<details>` inside morphed regions need `data-preserve-attr="open"`.
